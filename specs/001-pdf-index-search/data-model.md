# Data Model: PDF Index and Search

**Feature**: PDF Index and Search CLI  
**Created**: 2026-04-07

## Entities

### PDFDocument

Represents a PDF file discovered and processed during indexing.

**Attributes**:
- `id` (string): Unique identifier for the document (e.g., hash of file path + modification time)
- `file_path` (string): Absolute path to the PDF file
- `filename` (string): Extracted filename for display
- `file_size_bytes` (integer): Size of the PDF in bytes
- `indexed_at` (datetime): Timestamp when the document was indexed
- `extraction_status` (enum): One of `success`, `partial_extraction`, `failed`
- `extraction_error` (string, optional): Error message if extraction failed
- `total_chunks` (integer): Count of text chunks created from this document

**Validation**:
- `file_path` must exist and be readable at indexing time
- `file_size_bytes` must be > 0
- `total_chunks` must be ≥ 0; zero indicates extraction failure

**Purpose**: Track document metadata and extraction state for index management and error recovery.

---

### TextChunk

Represents a sentence-level text segment extracted from a PDF and embedded into the vector database.

**Attributes**:
- `id` (string): Unique identifier (combination of document_id + chunk_index)
- `document_id` (string): Reference to the PDFDocument
- `chunk_index` (integer): 0-based position of this chunk within the document
- `text` (string): The actual text content (typically a single sentence or short phrase)
- `char_offset_start` (integer): Character position in original extracted text
- `char_offset_end` (integer): Character position in original extracted text
- `embedding` (vector): Embedding vector (auto-generated by ChromaDB)
- `metadata` (dict): Additional context, e.g., `{ "page_number": 1, "section": "Introduction" }`

**Validation**:
- `text` must be non-empty and non-whitespace-only
- `chunk_index` must be ≥ 0
- `char_offset_start` ≤ `char_offset_end`
- `embedding` is generated by ChromaDB's default embedding model

**Relationships**:
- Many TextChunks belong to one PDFDocument
- Each TextChunk is stored in ChromaDB with its embedding for similarity search

**Purpose**: Enable semantic search by storing sentence-level segments with embeddings.

---

### SearchResult

Represents a ranked match returned when a user searches the index.

**Attributes**:
- `chunk_id` (string): Reference to the matching TextChunk
- `document_id` (string): Reference to the source PDFDocument
- `file_path` (string): The file path of the source document (denormalized for convenience)
- `matching_text` (string): The chunk text that matched the query
- `relevance_score` (float): Similarity score from ChromaDB (typically 0.0 to 1.0 or higher, depending on metric)
- `rank` (integer): Position in the sorted result list (1-based)
- `page_number` (integer, optional): Page number on which the match appears (if available in metadata)

**Validation**:
- `relevance_score` should be compared using library-specific thresholds (not assumed to be 0-1)
- `rank` must be > 0

**Purpose**: Present search matches to users in a structured, ranked order.

---

### IndexMetadata

Represents metadata about the entire vector database index.

**Attributes**:
- `index_version` (string): Version identifier for backward compatibility (e.g., "1.0")
- `total_documents` (integer): Count of successfully indexed PDFs
- `total_chunks` (integer): Total text chunks stored in the database
- `created_at` (datetime): When the index was first created
- `last_updated_at` (datetime): When the index was last modified
- `embedding_model` (string): Name of the embedding model used (e.g., "default", "all-MiniLM-L6-v2")
- `embedding_dimension` (integer): Dimensionality of the vector embeddings

**Validation**:
- `total_documents` ≥ 0
- `total_chunks` ≥ `total_documents` (every document contributes at least 1 chunk, or 0 if all failed)

**Purpose**: Enable version checking and migration, and provide diagnostic information about the index.

## Storage & Implementation Notes

- **ChromaDB Integration**: TextChunks are stored directly in ChromaDB as documents with metadata. The `document_id` is stored in the metadata field for later retrieval.
- **Embedding Generation**: ChromaDB automatically generates embeddings using its default embedding function (or a specified model).
- **Index File Location**: The index is stored in a local directory (e.g., `~/.less/index/` or in the current working directory), as specified in configuration.
- **No Direct Database**: All data is managed by ChromaDB; no separate relational database is required.

## Edge Cases

- **Unreadable PDFs**: If a PDF fails extraction, a PDFDocument record is still created with `extraction_status: failed` and `total_chunks: 0`.
- **Empty PDF**: A PDF with no readable text results in zero TextChunks for that document.
- **Large Documents**: Chunking is performed sentence-by-sentence using spaCy; very long sentences may result in single chunks larger than typical token budgets.
- **Search with No Results**: If no chunks exceed the relevance threshold, return an empty SearchResult list with a user-facing message.
